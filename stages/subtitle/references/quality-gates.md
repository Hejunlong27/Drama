# 质量闸门：六道机器断言 + 人耳审听包

> 本机通常**没有 vision provider**，所以"字幕画对了没有""漏了没有"必须尽量机器化，
> 剩下的才交给人耳，并且要**把需要人听的部分切好、切小**。

---

## 一、六道断言（每道都要有，缺一道就可能交付错字幕）

### 断言 1 —— 时间合法性

每条字幕：起点 ≥ 0、终点 ≤ 总时长、时长 ≥ 0.4 秒。

**实测踩到**：`seg13「真的？！」` 对齐只有 0.66 秒（下一句紧跟，无法延长）
⇒ 阈值设计成：**时长 < 目标 0.8s 只告警**（因为下一句紧跟时确实延不了），**< 0.4s 才判失败**。

**延长规则（容易写错）**：延长必须受**下一条起点**约束，否则两条字幕会叠在一起。

### 断言 2 —— 帧数一致

成片 `nb_read_frames` 必须等于母版帧数；母版帧数必须等于 **Σ各段帧数**。

```
ffprobe -v error -select_streams v:0 -count_frames \
  -show_entries stream=nb_read_frames -of csv=p=0 <file>
```

**为什么必须做**：`concat` + `-c copy` 在参数不完全一致时可能**成功退出但时间戳错乱** — 退出码不可信。

**ep03 实测**：14 段帧数之和 = **3980**；母版 3980；成片 3980 ✅

### 断言 3 —— ★ 字幕**真的画出来了**（像素自检）

本机没有 vision，所以用"有字幕/无字幕"两帧对比：

```
同一时间点分别抽帧：
  母版（无字幕）→ A 图
  成片（有字幕）→ B 图
比较：
  字幕带（y ≥ H - MarginV - 2.6×Fontsize）的像素差异  vs  画面其余部分的差异
  字幕带内的【近白像素】数量变化
判据：
  字幕带差异 ≫ 画面其余差异（局部性）  且  近白像素显著增加（白字黑边真的画上了）
```

**ep03 实测**：字幕带差异 **19.3** vs 画面其余 **0.9**（21 倍）；近白像素 **18 → 21786**

**为什么必须做**：字体名写错、字号为 0、ASS 路径错，**ffmpeg 都可能正常退出而画面上什么都没有**。
只看退出码就是"假绿"。

> 采样时**挑时长较长的条目**取中点，并测 3 条取最好的结果（避免恰好取到背景本身就很白的一帧）。

### 断言 4 —— 语速合理性

`语速 = 发音字数 / 时长`，须落在 `cps_ok` 区间（中文 `[2.0, 8.5]`，硬上限 `12.0`）。

🔴 **坑**：**标点不计入发音字数**。`「真的？！」` 是 **2** 个字不是 4 个 ——
按 4 个算会得出 11.1 字/秒，误判成"对齐错位"。

**作用**：能发现"对齐到很短的区间"这类问题；但**抓不住"整段前移/后移"**（那种情况语速只是"偏快"）
⇒ 必须配合断言 5。

### 断言 5 —— ★ 声学覆盖检查（**抓"字幕没对上"的硬判据**）

找出**有语音却没有任何字幕覆盖**的区间。

```
语音区间来源：**whisper 转写结果**（不是 silencedetect！）
   理由：silencedetect 会把背景音乐算成语音（实测 seg14 前 9.66s whisper 什么都没听到，
         silencedetect 却判为"有语音"）
   注意：whisper-cli 只吃 16k 单声道 WAV，直接喂 mp4 会静默失败
覆盖判定：该语音区间与所有字幕区间求交，若剩余 ≥ 0.6 秒 ⇒ 记为一个缺口
```

**ep03 实测**：
- 修好基准 bug 前：报 27 处 / 55 秒（噪音，因为"段内相对时间"减错了基准）
- 修好后：**5 处 / 23.2 秒** —— 全部是**台词真源缺失**，不是对齐错误
- **准确抓住了原 bug**：seg05/seg06 首句被推后 3.7/4.2 秒时，这条一抓就准

> 🔴 **易错点**：算"段内相对时间"必须减 **该段的起点（集内偏移）**，
> 不是减"该段第一条字幕的起点" —— 减错会让所有字幕整体前移，于是每段都误报。

## 断言 6 —— ★ 字幕安全区（平台硬性规则）

**判据（用户 2026-10-06 给定，中文剧与非中文剧同一口径）**

| 项 | 下限 |
|---|---|
| 距画面**底部** | **≥ 200px** |
| **文本框宽度** | **≤ 视频宽度的 70%** |

**为什么按像素而不是百分比**：平台口径就是像素。百分比会随分辨率漂移
（200px 在 1080×1920 上是 10.4%，在 2560×1440 上只有 7.8%）。
⇒ 配置存像素，实现取「配置百分比边距」与「安全区下限」的**较大值**，任何画布都满足。

**怎么断言**：`qa_safe_area(ass_path, cfg)` **回读写好的 ASS**，从 `PlayResX/Y` 与
`Default` 样式行的 `MarginL/MarginR/MarginV` 算出实际几何再判 —— 断言看**产物**，不看意图。
`--stage ass` 与"烧录前按实际分辨率重写 ASS"两处都会调用；不通过直接 `SystemExit`，不出片。

**★ 竖屏陷阱（必读）**：字号若只按**高度**百分比算，竖屏 1088×1920 会得到 129px，
而 16 字/行（中文字宽 1.0em）需要 2064px，远超安全区允许的 760px。
所以字号必须再受「文本框宽 ÷ 每行最多字符」**反向压住**：

| 画布 | 语言 | 按高度百分比 | 实际采用 | 文本框 | 占比 |
|---|---|---|---|---|---|
| 1440×832 横屏 | zh | 56px | **56px** | 1008px | 70.0% |
| 1440×832 横屏 | es | 54px | **46px**（被压） | 1008px | 70.0% |
| 1088×1920 竖屏 | zh | 129px | **47px**（被压） | 760px | 69.8% |
| 1088×1920 竖屏 | es | 125px | **34px**（被压） | 760px | 69.8% |
| 2176×3840 竖屏 2K | zh | — | **95px** | 1522px | 69.9% |

**想让竖屏字号更大，就走"减少每行字数"，不要动安全区**：12 字/行 → 63px。

**自测**：`python scripts/test_safe_area.py`
（三画布 × 两语言 + 负向篡改测试：手改 ASS 成"贴边字幕"，断言必须报失败）。

## 二、缺口分类（决定要不要找人听、找谁）

| 类别 | 特征 | 处置 |
|---|---|---|
| **台词真源缺失** | 语音内容不在 `<d>` 里（播报、画外音、上一句余音） | **切片段给人听** → 用户给文本 → 补进真源 |
| **对齐错位** | 语音内容**就是**某条台词，只是时间不对 | 改对齐算法，不需要人 |
| **非语音** | whisper 输出带括号（如 `(咱們在這裡)`）= 它自己标记的非语音；或音乐/音效 | 直接跳过，不用人听 |

**区分"真源缺失"和"对齐错位"的办法**：
看 ASR 转写出的文本 **是否与某条 `<d>` 台词内容匹配** ——
匹配 ⇒ 是对齐问题；不匹配（乱码/别的词）⇒ 是缺失内容，需要人耳。

## 三、人耳审听包（**交付给用户时必做**）

**原则**：用户不该自己去视频里找位置。**把每一处可疑点切成 3–5 秒的小音频**。

```powershell
# 每个缺口切 [起点-0.5s, 终点+0.5s]
ffmpeg -y -ss <起点-0.5> -t <缺口时长+1.0> -i <段>.mp4 -vn -c:a libmp3lame -q:a 5 clipNN_<段>.mp3
```

**配套给一张裁决单**（Markdown 表格）：`编号 / 段 / 时间 / ASR 听到的 / 该段剧本台词 / 音频文件`

**ep03 实测规模**：5 处 / 合计 **24 秒音频** / 5 个 mp3 / 共 193 KB。

**裁决只需二选一**：
- **A 要进字幕** → 用户把听到的内容告诉你，补进真源
- **B 不进字幕** → 接受漏掉

## 四、交付检查清单（每次交付前逐项打勾）

- [ ] 六道断言全过（失败就**不出片**，不要"先交付再修"）
- [ ] 成片帧数 == 母版帧数 == Σ各段帧数
- [ ] 像素自检通过（字幕带差异 ≫ 其余，近白像素显著增加）
- [ ] 覆盖缺口已列出，并**切成审听片段**一起交付
- [ ] 抽了 2–4 张**样张 PNG**（用户秒看样式，不用等视频）
- [ ] `report.json` 落盘（含全部自检原始数据，可复核）
- [ ] 向用户如实说明：哪些是机器保证的（时间轴）、哪些需要人耳（漏没漏）

---

## 五、这些断言的边界（**不要夸大**）

| 断言能保证 | 断言**不能**保证 |
|---|---|
| 时间轴落在实测语音上 | 台词**有没有漏**（只能报警，需人耳） |
| 字幕确实渲染出来了 | 字幕**画得好不好看**（字体观感、断行美感） |
| 没有重叠、没有失败条目 | 译文/文案**写得对不对** |
| 拼接帧数零丢失 | 画面**内容**对不对（人物一致性等，那是上游的事） |

> **一句话**：本 Skill 是"**一致性守门员**"，不是"**质量提升器**"。
