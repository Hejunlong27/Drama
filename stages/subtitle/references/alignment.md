# 对齐算法：为什么、怎么做、怎么验

> 本文件是字幕链路最核心也最容易做错的部分。**先读完这一页再动对齐代码。**

---

## 一、为什么不能用剧本里的镜头切点

提示词里每条台词上方有 `[Shot N] 在 XX.XXX，切至…`。这是**镜头切换点**，不是台词起点：

| 段 | 台词 | 剧本切点 | 实测语音起点 | 偏差 |
|---|---|---|---|---|
| seg03 | 林主任……既然你都追到这儿了 | 13.00 | 9.36 | **−3.64s** |
| seg05 | 陆鸣！你胡闹什么？！ | 0.00 | 0.08 | +0.08s ✅ |
| seg06 | 啊？！更……更严重了？！ | 0.00 | 0.20 | +0.20s ✅ |
| seg13 | 走！订机票，去三亚看海吃海鲜！ | 8.00 | 5.82 | **−2.18s** |

**统计**：29 行比对，偏差 ≤0.5s 仅 10 行（34%），**>1s 有 15 行（52%）**，中位 1.02 秒、最大 5.00 秒。

⇒ **切点只能当"初值/报警参考"，绝不能当字幕时间。**

> ⚠️ 注意：拿"整段一起对齐"的结果去比对切点，得到的"偏差"里**混着对齐器自身的偏差**。
> 早期的"52% 偏差"结论要用**顺序约束对齐**重算才算准。别把两种误差混为一谈。

## 二、核心方法：顺序约束的逐条对齐

### 算法

```
cursor = 0
for 每条台词 i:
    把 [cursor, 段尾] 这段音频切出来 → win_i.wav
    只把这一条台词的文本喂给对齐器
    得到相对时间 [s_i, e_i] → 绝对时间 = cursor + s_i / cursor + e_i
    cursor = 绝对 e_i          ← 关键：下一条只能从这条结束之后开始
```

**为什么必须"顺序约束"**：单纯逐条对齐时，每条都在**整段音频**里找最佳位置，
于是两条可能抢到同一区间（实测 seg07 两行区间重叠 —— 物理上不可能）。

### 为什么不能"整段台词一次性对齐"

把 n 条台词一起喂给 CTC，对齐器会把**全部文本**在**整段音频**上重新分配。
当音频里某处存在与首句**声学相似**的片段时，首句会被吸过去，整段文本向后挤。

**实测证据**：

| 段 | 行 | 整段一起对齐 | 真值 | 偏差 |
|---|---|---|---|---|
| seg05 | 1 | **3.72s** | 0.08s | **+3.64s** |
| seg06 | 1 | **4.42s** | 0.20s | **+4.22s** |

### 决定性隔离实验（怀疑对齐时照做）

```powershell
# 只取该段前 3.5 秒，只对齐"首句"
ffmpeg -y -t 3.5 -i <段>.mp4 -vn -ar 16000 -ac 1 -c:a pcm_s16le head.wav
ctc-forced-aligner --audio_path head.wav --text_path 首句.txt --language cmn --split_size char --romanize
# 实测结果：首字 0.08–0.20  ✅ 完全正确

# 再从 3.0s 处截同样时长，对齐同一句
ffmpeg -y -ss 3.0 -t 3.5 -i <段>.mp4 -vn -ar 16000 -ac 1 -c:a pcm_s16le mid.wav
ctc-forced-aligner --audio_path mid.wav --text_path 首句.txt ...
# 实测结果：也能"匹配"上（0.02–0.76）⇒ 证明 3.0s 附近确有相似片段
```

**结论**：单条对齐时结果正确；问题出在"多条一起"。⇒ 隔离实验是判断"对齐器错还是素材本来就这样"的最快手段。

## 三、两个已验证并否掉的弯路（**不要重踩**）

### 弯路 1：改 `--star_frequency segment`

现象是"首句被推后"，看起来像开头那个 `<star>` 占位 token 吃掉了时间。
实测：`segment` 修好了 seg05/seg06，**却改坏了 5 处**——seg04 从正确的 2.52 变成错误的 0.46
（0.46 落在 silencedetect 判定的**静音区** 0–0.49 里，明显是错的）。

⇒ **弃用。** 而且单条对齐时 `edges`（默认）反而最好：`edges` → 0.08–1.94 正确；`segment` → 尾巴被拉到 3.48。

**最终配置**：`--split_size char --romanize --star_frequency edges`（配合顺序约束逐条对齐）。

### 弯路 2：朴素逐条对齐

每条独立在整段音频里找最佳位置 ⇒ 各行互相抢占同一区间。
⇒ 必须加"下一条从上一條结束之后开始"的约束。

## 四、对齐器安装与必踩的坑

### 安装（**不要用 PyPI**）

```powershell
# ❌ pip install ctc-forced-aligner  ← PyPI 上那个是同名的另一个包（Deskpai.com），
#    它的 main.cpp 只定义了 align_sequences，没有 PyInit_align_ops，链接必然失败，谁都编译不过
# ✅ 从 GitHub 源码装（需要 MSVC C++ 生成工具，装 VS Build Tools 的「使用 C++ 的桌面开发」）
pip install https://github.com/MahmoudAshraf97/ctc-forced-aligner/archive/refs/heads/main.tar.gz
```

本机位置：独立 venv（本机在 `C:\align-env`；torch 2.14.0+**cpu**，刻意避开 2.5GB 的 CUDA 包）。

### 三条硬要求

| 要求 | 不遵守的后果 |
|---|---|
| **`PYTHONUTF8=1`** | 读 UTF-8 中文文本报 `UnicodeDecodeError: 'gbk' codec`（它用系统默认编码 open） |
| **`HF_ENDPOINT=https://hf-mirror.com`** | 权重从 HF 拉，直连不通 |
| **`--romanize`** | 内部断言失败 `AssertionError: <star> != 好` |

### 参数语义

| 参数 | 值 | 说明 |
|---|---|---|
| `--language` | **`cmn`** | 中文的 **ISO 639-3** 码（**不是 `zh`**）；西语 `spa` |
| `--split_size` | `char` | 字符级 —— 字幕需要的粒度 |
| `--romanize` | 必加 | 非拉丁文字必需 |
| `--star_frequency` | **`edges`（默认）** | **不要改成 segment**（见弯路 1） |
| `--alignment_model` | 默认 | `MahmoudAshraf/mms-300m-1130-forced-aligner` |
| `--merge_threshold` / `--context_size` | 测过**无影响** | 不用调 |

### 输出位置（曾为此白等半天）

**结果写到「音频同名」的 `.txt` 与 `.json`，不打印到 stdout。**
`.txt` 每行形如 `2.32-3.96: 好`（字符级起止秒）。

> ⚠️ 别把输入文本文件命名为与音频同名 —— 对齐输出会**覆盖**你的输入。

## 五、没有台词文本时的备选路线

本 Skill 的主线是"**已有文本 → 强制对齐**"。若文本缺失：

1. **只判断"有没有对白"**：ffmpeg 自带 whisper 滤镜即可（`-af whisper=model=…`），最省事。
   但它的**时间戳不可复现**（流式实时队列，切块依处理速度而变），**绝不能用于字幕时间**。
2. **要拿到时间**：用 whisper.cpp CLI（本机 `whisper-cli.exe`，确定性、可复现，14 段仅 21.5 秒），
   或先转写再人工校对文本，再回到主线做强制对齐。
3. **whisper-cli 只吃 16 kHz 单声道 WAV** —— 直接喂 mp4 会**静默失败**（无输出、无报错）。

## 六、怎么验证对齐是对的

| 手段 | 能回答什么 | 成本 |
|---|---|---|
| **silencedetect**（纯声学，与模型无关） | 这一段哪里有声、哪里静默 ⇒ 台词起点该落在哪个有声区 | 秒级 |
| **whisper 转写**（确定性） | 那里说的是什么（文本可用于匹配"是不是这句台词"） | 14 段 21.5 秒 |
| **同一条台词在前 N 秒内单独对齐** | 对齐器错还是素材本来如此（隔离实验） | 秒级 |
| **语速合理性**（发音字数 / 时长） | 明显异常（>8.5 字/秒）⇒ 强烈提示对齐错位 | 0 |
| **声学覆盖检查** | 有语音却没字幕覆盖 ⇒ 对齐错位**或**台词缺失 | 秒级 |

**最有效的组合**：silencedetect 定"语音在哪"+ whisper 定"说的是什么"+ 顺序约束对齐定"精确到 0.1 秒"。
