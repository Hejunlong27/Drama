# SoloDrama 生产流程总纲（单一真源）

- 版本：v1.0 ｜ 日期：2026-10-16
- 地位：**本文档是短剧生产「流程 · 目录规范 · 硬规则 · 门禁」的唯一真源。**
  与各 Skill 的说明冲突时，**以本文档 + 仓库代码为准**；Skill 只提供方法论与提示词资产。

## 二、工作区分阶段目录规范（`layout.json` v1）

```
<剧项目>/
├── model-plan.json       通道确认单（生图/视频 + 执行依据）
├── project.json          创作层状态
├── layout.json           ← 目录布局声明（本规范的可执行形式）
├── 01-调研/              市场数据 · 多市场对比 · 爆款拆解
├── 02-选题/              候选池 · 七维评分 · 定位卡 · brief
├── 03-剧本/              集数规划 · ep_XX.md · 圣经(bible) · 台词时长审计
├── 04-资产/              资产卡（人/场/道）· 参考图原图 · refs.json
├── 05-分镜/              分镜脚本（11 字段）
├── 06-提示词/            H3 六段式 md + **data/ 四文件**（出片引擎唯一输入契约）+ refs_h3/
├── 07-成片/              <批次>/ · assets/ · subs/<ep>/ · logs/
├── 08-合规/              合规预检记录 · 整改说明 · 申诉材料
├── 09-发行/              封面 · 文案 · 发布清单
└── video-pipeline/       引擎技术目录（config.*.json / ledger / runs）
```

**三条纪律**

1. **不重叠**：同一份产物只在一个阶段目录里写。阶段之间靠**引用**衔接（例如 `06-提示词/refs.json` 指向 `04-资产/` 的图片，不复制）。
2. **技术目录不参与创作**：`video-pipeline/` 只放引擎配置、台账、日志；**不要**往里面放剧本或提示词。
3. **向后兼容**：没有 `layout.json` 的旧工作区仍按
   `video-pipeline/data` + `video-pipeline/output` 解析，**行为完全不变**。
   解析链（`stages/_layout.py`，唯一真源）：
   `<engine_root>/config.local.json` 的 `data_dir`/`out_dir` → `<ws>/layout.json` → 旧默认。

> 新建项目：`python stages/creation/scripts/creation.py scaffold --workspace <ws> --slug <s> --title <t>`
> 会自动建全部阶段目录、写 `layout.json`、并把 `data_dir`/`out_dir` 回填进 `config.local.json`。
> 查询当前布局：`python stages/_layout.py --workspace <ws>`。

## 三、硬规则台账（不可调优，改配置只为显式声明）

### 3.0 画风三轨规格（★ 最先锁，不可事后更换）

来源：MiniMax 官方半解说短剧技能族。**完整规格见 `docs/styles/画风三轨规范.md`**，此处只列会被机器校验的硬值。

| 项 | 3D 漫剧 | 2D 动画 | 真人写实 |
|---|---|---|---|
| `visual_style_lock` | `3D-manhua-cel` | `2D-cel-webtoon` | 无（摄影真实感） |
| 单镜时长 | 6–10s（动作 4–6s） | 4–10s | 5–15 整数秒 |
| 旁白字数上限（普通/情绪/大段） | 28 / 32 / 36 | 32 / 36 / 40 | 60 / 70 / 80 |
| 旁白/对白最小间隔 | 0.30s | 0.20s | 0.20s |
| 尾缓冲 | 0.30s | 0.20s | 0.20s |
| 角色资产 | 主卡 **+ 三视图** | 主卡 | 主卡（16:9 纯白，左脸特写 + 右三视图半身） |
| 场景资产 | 主卡 **+ 辅卡** | 主卡 | 主卡（16:9 纯白，**无人物**） |
| 道具卡上限 | 1 | 1 | 0 |
| 重置锚周期（主角/配角/场景） | 4 / 6 / 5 | 3 / 5 / 4 | 不设 |
| 首帧锚点 | **强制 + 角度必须匹配** | 可选 | 单格干净图 |
| 分镜拓扑 | 逐镜 | 逐镜 | **1 片段 = 1 张三格时间分镜** |
| 交付终点 | 无旁白成片 + 独立旁白包 | **旁白交接（不出成片）** | 成片 + 旁白 + 可选字幕 |

**半解说结构四件套（三轨共用，可机器校验）**
① 旁白承担背景/时间跳转/内心；② 对白承担冲突/揭示/反转；③ **旁白与对白零重叠**；④ 结尾留悬念或收束。

```powershell
python stages/production/scripts/drama.py style status                  # 画风门禁
python stages/production/scripts/drama.py halfcheck all                 # 三类硬校验（读 05-分镜/storyboard.json）
```

### 3.1 平台硬限

| 规则 | 值 | 出处 / 后果 |
|---|---|---|
| RunningHub 单账号并发 | **≤ 5** | 平台硬限；超限提交被拒（退避重试，仍失败降并发到 1） |
| H3 图片槽 | **≤ 6** | 改不了；超了末尾图被丢弃并**错位** |
| 单段参考图 | **≤ 6** | 同上 |
| 参考图上传有效期 | 约 24 小时（缓存 20h） | 过期需重传 |
| 视频单次生成时长 | 4–15 秒 | H3 口径 |
| 字幕安全区 | 距底 **≥200px**、文本宽 **≤70%** | 竖屏字号须由「行宽 ÷ 每行字数」反向压住 |
| 语速区间 | zh `[2.0, 8.5]`，硬上限 12 | 超生理上限（zh 20 / es 40）中止 |

### 3.2 创作口径

| 规则 | 值 |
|---|---|
| **默认集数** | **40 集**（2026-10-16 定为 40；由 30 上调） |
| 单集时长 | **70 秒**（lint 口径 70–95 秒）；单镜 4–15 秒；每集 **5–12 镜** |
| **台词折算语速** | **4.2 字/秒**（含正常停顿） |
| 单元容量 | 30s→上限 100 字 / 目标 60–90；15s→55/25–50；10s→35/18–32 |
| 超载判定 | `>上限` 超载；`< 45 字`（30s 单元）偏轻 |
| 爆点节拍 | 中型每 **4** 集、大型每 **10** 集（与 60 集口径的 6/15 **密度一致**） |
| 选题候选数 | 8–12 个；同批主赛道重合度 ≤40% |
| 七维评分 | 权重 `20/12/15/13/12/13/15`；总分 `Σ(维度分×权重)×10`；S≥85 / A 75–84.9 / B 65–74.9 / C 55–64.9 / D<55 |
| 一票否决 | `合规 ≤3` → 强制 D；`独特性 ≤3` → 总分封顶 **74.9** |
| 七维真源 | `stages/creation/references/scoring-model.md`（**唯一真源**，Skill 侧仅基线快照） |

### 3.3 留存率导向的剧本结构（★ 2026-10-16 新增）

> 背景：用户实测几部剧「内容吸引度不够」→ 把留存要求升级为**可机器校验的硬结构**。

**每集四件套（缺一即返工，`script_rewrite.lint` 会拦）**

| 字段 | 含义 | 硬要求 |
|---|---|---|
| `cold_open` | 开场钩子 | 前 **3–5 秒**内必须出现「异常 / 冲突 / 悬念」之一 |
| `core_conflict` | 核心冲突 | 明确「谁 vs 谁 vs 什么」 |
| `reversal` | 一次反转 | 必须**改变力量对比或信息格局**（仅情绪起伏不算） |
| `hook` | 集尾钩子 | 类型**不得与前两集连续重复** |

**留存三段**

| 段 | 集数 | 要求 |
|---|---|---|
| 拉新攻坚 | EP1–3 | 三连强钩子链（身份悬念→危机逼近→秘密揭露）；**禁止铺垫集、禁止慢热** |
| 留存活口 | EP4–10 | 每集至少一次「小爽」落点；中段不得连续两集无爆点 |
| 转化与收束 | EP11+ | 按爆点节拍推进；**收尾前 2 集必须再拉一次强钩子** |

**EP1 = 黄金 3 秒**：把全剧最高冲突前置到开场，禁止背景铺垫开场。

### 3.4 合规红线（发布前必过）

| 规则 | 值 |
|---|---|
| 发布前三问 | ①方法是否出现 ②主体是否出现（含背景/倒影/屏幕）③身份是否歧义（校服/童装风）—— **全「否」才可发布** |
| AIGC 标注 | AI 用于真实还原人物或场景时**必须明确标注**（未标注 = 降流） |
| 受限集数占比 | **≤ 10%**；`余量 = ceil(0.1 × 总集数) − 已受限` |
| 通用安全拍法 | 死亡情节一律「**镜头外发生 → 事后发现 → 以调查与对白推进**」 |
| 整改三硬标准 | 主体不出现 / 方法不出现 / 身份不歧义 |

> 可机器执行部分：`python stages/production/scripts/compliance_precheck.py --workspace <ws> --ep ep01 --q1 no --q2 no --q3 no`

### 3.5 成本口径

| 项 | 值 |
|---|---|
| 单段出片 | ≈ **145 RH币/段**（保守 210） |
| 失败率 | ≈ **10%**（实测 9.1%，**全部未计费、重跑即过**） |

## 五、交接契约（阶段之间只认契约，不认对话）

| 交接 | 契约 | 校验命令 |
|---|---|---|
| 创作 → 资产 | 资产卡 md（`#### {CH/SC/PR}##` + `· 字段`） | `stages/assets/scripts/asset_md.py --list` |
| 资产 → 提示词 | `04-资产/refs.json`（key → 图片路径） | `ingest_check.py` 的参考图存在性检查 |
| 提示词 → 出片 | **`data/` 四文件**（`shots/characters/scenes/h3_prompts.json`） | `ingest_check.py` + `run.py --dry-run --strict` |
| 出片 → 成片 | `07-成片/<批次>/<shot_id>/final.mp4` + `state.json` | `drama.py video status <批次>` |

**三条不可违反的接线规则**

1. `<Picture N>` 对**全部 Subject 顺序编号**，`character_refs[i]` 顺序喂第 i 个槽 —— **缺一号后面全错位**；不能把场景图追加到末尾蒙过去。
2. `<d>[语言] 台词</d>` 是**字幕真源**；`[Shot N] At MM:SS.mmm` 时间戳必须与 `duration` 一致（否则镜头节奏被等比压缩）。
3. `data/` 四文件是**只读契约**；缺关键字段**报错让人补，不猜不编**。

## 六、失败处置（口径固定，不得临时发明）

| 失败类型 | 处置 |
|---|---|
| 出片「工作流运行失败」 | 先按 transient：`video run --yes --resume <批次> --only <段>`，**别改提示词/配置** |
| 提交成功但轮询失败 | 直接 `--resume`（复用 taskId，只轮询不重复扣费） |
| 传输层异常（错误信息为空） | 指数退避 + `--submit-gap 2` 节流 |
| 连续失败熔断 | 熔断即停整批，先排障再续跑 |
| 放大中断 | **整集重跑**（暂不支持断点续跑）；Topaz GPU 独占，一次一集 |
| 对齐失败 | 引擎三级降级；整集断言失败 = **中止交付并报告**，不静默通过 |
| 清理文件 | **绝不用通配符**（曾误删 7 个交付成片）；批量删除分批 ≤10 |
